# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Single-page static HTML portfolio site for Santiago Miranda (QA Engineer — API & Accessibility Testing). No build tooling, no package manager, no framework — `index.html` is the entire site: CSS lives in an inline `<style>` block, and a small vanilla `<script>` block at the end of `<body>` drives the background/typewriter effects (see Animations below).

This is a **portfolio**, not a CV mirror: it exists to show hiring managers how Santiago tests and what role he's after, not just where he worked. The CV (Onetree/Globant employers, metrics) grounds the content, but two sections go beyond it — `02. como_trabajo` (testing judgment/criteria, not a tool list) and `04. evidencia` (a sample defect report). Don't collapse the site back into a CV summary.

## Development

There is no build/lint/test tooling. To preview changes, just open `index.html` directly in a browser (or serve the folder with any static file server).

## Design decisions

- `.projects-grid` is `minmax(360px, 1fr)` on purpose → two columns at desktop, not three. Three columns of Problem/What I did/Impact copy at ~260px read as text walls; don't shrink it back.
- `04. evidencia` cards are styled as **files**, not as more project cards: each `.evidence-item` starts with a `.file-tab` strip (`evidence/<filename>`, `aria-hidden`, purely visual) and wraps the rest in `.evidence-item__body`; the card has a gold left border and a darker surface. This is the one deliberate visual differentiator on the site — keep it to the evidence section only. New evidence cards must follow the same structure (tab + body) or the flex layout / `.risk-note` bottom alignment breaks.
- Card body text uses `--muted-3` (#bcb1d4, 0.92rem). `--muted-2` is still used elsewhere; don't drop card copy back to it.
- `html` carries a solid dark `background` and `color-scheme: dark` (plus a `<meta name="color-scheme" content="dark">`), and every `backdrop-filter` has a `-webkit-backdrop-filter` twin. Reason: the LinkedIn in-app browser on iOS rendered the viewport canvas white (body gradient not painted), which washed out the whole site. Never move the base dark color off `html`.
- There is a global `:focus-visible` style (2px gold outline, offset) — never add `outline: none`. The evidence-2 sample is about focus contrast (1.4.11), so the site itself must show a visible focus ring.
- The footer carries a claim line ("keyboard-navigable · WCAG AA contrast · no trackers · no frameworks"). It must stay true: contrast ratios for all text/background pairs were computed (all ≥ 5.5:1; the old footer gray #6f6484 failed at 3.6:1 and was replaced by #8d82a6), keyboard tabbing was verified, there are no analytics/scripts beyond the inline one, and fonts are the only external request (Google Fonts). If any of that changes, change or remove the line — don't let it become a false claim.

## Animations

All in the inline `<style>`/`<script>` blocks, no dependencies, and all respect `prefers-reduced-motion: reduce`:

- Scroll-reveal fade/slide-in via `.reveal` + `IntersectionObserver` (header, sections, project cards).
- Background: panning grid (`grid-pan`), three drifting/hue-rotating aurora blobs (`.bg-glow`), and randomly-generated rising particles (`.bg-particles`, populated in JS).
- Statusbar path (`#typewriter`) cycles through `santiago-miranda` / `qa_engineer` / `istqb_ctfl` with a letter-by-letter type/delete loop; first word holds longer (8s) than the others (5s).
- Small hover/idle details: status-dot pulse, role-pill sheen sweep, project-card top-border grow-on-hover.
